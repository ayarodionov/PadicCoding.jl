Ternary p-adic Coder

Animated runs of the revised p-adic arithmetic coder with P = 3 on the grid G(35): 243 cells, each a leaf of the ternary coding tree. Encode narrows an interval [l, r); when the tree paths to l and r−1 share a prefix, those trits are output and the interval is rescaled (PR). When the interval hugs ⅓ or ⅔, it is stretched ×3 around that point and one trit is deferred (AR). Decode replays the same moves with a point g read from the code. Both traces match padic_encode / padic_decode with P = 3 digit for digit.

Reading the picture

A grid index x written in 5 ternary digits, most significant first, is the path from the root to leaf x (0 = left, 1 = middle, 2 = right). Read from the leaf upward, the same digits form the 3-adic integer x^; the IP transform ^ only reverses them.

The 3-adic distance |l^ − (r−1)^|₃ = 3^−n, where n is the length of the shared path. Once it drops below 1, the interval lies in one subtree and its n path trits are final.

The decoder holds the next 5 code trits as a grid point g. Each rescaling shifts digits out of the top of g and new code trits into its bottom, so g stays inside the interval and picks out each symbol.

Unlike P = 2, there are two level-1 points, ⅓ and ⅔. AR rescaling remembers which one it stretched around (the stable point) and how many times. The width stays at least 1/P² + 1/Pᴺ, so the total frequency may be at most 3³ + 1 = 28.
